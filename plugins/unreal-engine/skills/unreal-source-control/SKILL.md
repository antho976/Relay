# Unreal Source Control

Code, config and project files are text and merge like any code. `.uasset` and `.umap` files
are binary: **they cannot be merged**. Two people (or agents) changing the same asset means
one of the changes is lost. Everything in this skill exists to prevent that.

Reference files (complete, ready to copy):
- `reference/gitignore-template.md` - read when creating or auditing `.gitignore`.
- `reference/gitattributes-template.md` - read when setting up Git LFS and locking.

## 1. What goes in the repo

| Path | Commit? | Why |
|---|---|---|
| `<Project>.uproject` | Yes | Text (JSON): modules, plugins, engine association |
| `Source/` | Yes | C++, `*.Build.cs`, `*.Target.cs` |
| `Config/` (`Default*.ini`, platform folders) | Yes | Project settings; review every diff |
| `Content/` | Yes, via LFS | All `.uasset`/`.umap`, including `__ExternalActors__`/`__ExternalObjects__` |
| `Plugins/<P>/` (`.uplugin`, `Source`, `Content`, `Resources`) | Yes | Same rules as the project |
| `Build/` platform resources (icons, Android/iOS files) | Yes | Needed to package |
| Raw source art (`.fbx`, `.psd`, `.blend`, `.wav`) | Team choice, via LFS | Often kept in a separate `SourceArt/` folder or repo |
| `Binaries/`, `Plugins/*/Binaries/` | No (usually) | Build output. Exception: teams whose artists have no compiler sometimes commit editor binaries, or distribute them with Unreal Game Sync; decide deliberately |
| `Intermediate/`, `Plugins/*/Intermediate/` | Never | Generated (`*.generated.h`, UHT/UBT output, Python stub) |
| `Saved/` | Never | Logs, autosaves, crashes, per-user config (`Saved/Config`), screenshots |
| `DerivedDataCache/` | Never | Local cache of shaders/derived data; rebuilt automatically |
| `.vs/`, `*.sln`, `*.suo`, `.idea/`, `*.xcworkspace` | Never | Generated IDE files (regenerate: `unreal-build-packaging`) |

`*_BuiltData.uasset` (baked lighting/reflection data) is regenerated by lighting builds. Commit
it if the project uses baked lighting and people should not have to rebuild; many UE5
projects using Lumen have none. Pick one policy and state it in the repo README.

## 2. Git LFS setup

1. Install once per machine: `git lfs install`.
2. Copy `reference/gitattributes-template.md`'s content into `.gitattributes` **before**
   the first asset is committed. Commit `.gitattributes` alone first.
3. Verify: `git check-attr -a Content/Maps/Main.umap` shows `filter: lfs` and `lockable: set`;
   after adding assets, `git lfs ls-files` lists them.
4. An existing repo with assets already committed as normal blobs needs
   `git lfs migrate import --include="*.uasset,*.umap" --everything`, which **rewrites
   history** and requires every clone to re-clone. That is a human decision; never run it unasked.
5. The host must support LFS (and LFS locking for section 3). GitHub, GitLab, Bitbucket and
   Gitea do; check storage and bandwidth quotas, since UE content grows fast.

## 3. Locking binary assets

With `lockable` in `.gitattributes`, Git LFS checks lockable files out **read-only** until
you lock them. This is the git equivalent of Perforce exclusive checkout.

```
git lfs locks                                   # who holds what
git lfs lock Content/Maps/Main.umap             # take the lock before editing
git lfs unlock Content/Maps/Main.umap           # after your commit is pushed
git lfs locks --path=Content/Characters/Hero/BP_Hero.uasset
```
- Enable push verification so pushes that modify files locked by someone else are refused:
  `git config lfs.<remote-lfs-url>.locksverify true` (Git LFS prompts for this the first time).
- The editor shows read-only assets as not writable and may offer to "make writable";
  making it writable without taking the lock defeats the system. Take the lock instead.
- Locks are per server, not per branch: a lock on `main` blocks the same path on every branch.
- Unlock only after the change is pushed. `git lfs unlock --force` breaks someone else's lock;
  only a human may decide that.

## 4. Rules for agents (and anyone sharing assets)

1. **Before modifying any `.uasset`/`.umap`** (through `unreal-editor-automation`):
   - run `git lfs locks` and `git status`; if another user holds the lock or the file has
     uncommitted changes that are not yours, **stop** and tell the human;
   - take the lock (`git lfs lock <path>`) if the repo uses locking;
   - make sure you are on an up-to-date branch (`git pull` first) so you edit the latest version.
2. **One agent per map.** Never have two sessions editing the same level (or the same
   World Partition region) at once. Split work by map, by asset folder, or by actor with OFPA.
3. Prefer text: move logic into C++/config/Data Tables built from CSV, so work merges.
   Keep Blueprints thin (`unreal-blueprints`, `unreal-cpp`).
4. Keep asset changes small and commit them promptly with a message listing each changed
   asset; do not leave locked assets idle.
5. Never resolve a binary conflict by "merging". See section 7.
6. Never rename/move/delete assets with `git mv`/`rm`; use the editor (section 6).
7. Do not commit files you did not intend to change. The editor dirties packages on load
   (resaves, version upgrades); revert unrelated binaries with `git restore <path>`
   unless the human wants them.

## 5. One File Per Actor (OFPA) and World Partition

A classic `.umap` stores every actor in one file: two people moving two different lamps
conflict. With **One File Per Actor**, each actor instance is saved as its own small
package under `Content/__ExternalActors__/<map path>/...` (and some objects under
`Content/__ExternalObjects__/`), and the `.umap` itself changes rarely.
- World Partition maps (the default Open World template in UE5) use OFPA automatically.
- Non-World-Partition levels can be switched to external actors in the editor (the option
  is in World Settings / level conversion options depending on version; check the docs for
  your version before telling the human where it is).
- The file names under `__ExternalActors__` are hashed, not actor labels. Commit the whole
  set the editor changed; the editor's **Revision Control > View Changes** (5.x) shows
  which actors they correspond to.
- Adding/deleting actors adds/deletes files: commit deletions too (`git add -A Content/`
  scoped to the paths you changed).
- OFPA reduces conflicts; it does not remove the need to coordinate on the same actor,
  the level's World Settings, or shared Data Layers.

## 6. Redirectors

Renaming or moving an asset in the editor leaves an **ObjectRedirector** at the old path
so unsaved/unloaded referencers still work.
- After a move/rename, fix redirectors: Content Browser > right-click the folder >
  **Fix Up Redirectors** (or the scripted recipe in `unreal-editor-automation`). This resaves
  every referencer and deletes the redirectors.
- Commit the moved assets, all resaved referencers and the deleted redirector files **in
  one commit**. Committing only the moved asset breaks every other clone.
- Referencers must be lockable by you: fixing redirectors touches many files, so do it
  when nobody else is editing those assets, ideally on a quiet branch/time.
- Renames of C++ classes/properties need `[CoreRedirects]` in `DefaultEngine.ini` instead
  (`unreal-build-packaging`).

## 7. Conflicts

Text files (C++, ini, `.uproject`): resolve normally. For `.uproject`/`.uplugin` keep valid
JSON; for ini files keep both sides' keys unless they are the same key.

Binary assets:
1. Decide which side wins (ask the human if both changes matter).
2. Take it: `git checkout --theirs -- <path>` or `git checkout --ours -- <path>`, then
   `git add <path>`. During a **rebase** the meaning of ours/theirs is swapped: `--ours` is
   the branch being rebased onto.
3. Re-apply the losing side's change by hand in the editor (or re-run the script that made it).
4. Open the asset in the editor after resolving to confirm it loads; check `ue_log`.

The editor's Blueprint diff (right-click asset > Revision Control > Diff Against Depot,
with a revision control provider configured) shows what changed visually; it cannot merge.

## 8. Config (.ini) files

- Project settings changed in the editor are written to `Config/Default*.ini`. The editor
  often rewrites whole sections, reorders keys, or adds defaults; review diffs and commit
  only intended keys.
- Per-user editor settings live in `Saved/Config/` and must not be committed. Settings you
  want shared belong in `Config/DefaultEditor.ini` or `DefaultEditorPerProjectUserSettings.ini`.
- Array syntax: `+Key=Value` adds, `-Key=Value` removes, `!Key=ClearArray` clears. Merge
  conflicts on array lines usually mean "keep both".
- Never commit secrets (API keys, passwords, signing keystores' passwords) in ini files.

## 9. Perforce

Perforce (Helix Core) is Epic's standard: exclusive checkout of binary files, streams,
Unreal Game Sync (UGS) for distributing precompiled editor binaries, and first-class editor
integration. Large teams with many artists usually choose it. Minimum typemap so binary
assets are exclusive-lock:
```
TypeMap:
    binary+l //....uasset
    binary+l //....umap
    binary+l //....psd
    binary+l //....fbx
    binary+w //....exe
    binary+w //....dll
    text //....ini
    text //....uproject
    text //....uplugin
```
Use a `.p4ignore` with the same entries as the gitignore template, and set `P4IGNORE`.
Configure the editor via Revision Control > Connect to Revision Control. The agent rules
in section 4 apply identically: check out (lock) before editing, one editor per map.

## 10. Editor revision control integration

The editor can talk to Git (a Git provider ships with the engine; community plugins add
LFS locking support) and Perforce: File/toolbar **Revision Control** menu > Connect. With
a provider connected the editor shows lock/checkout state on assets and offers check out
on edit. Whether it is configured is the human's choice; the git CLI rules above work either way.

## Relay tools for this work

- `ue_asset_refs {path}` before moving, renaming or deleting anything: it lists what depends on the
  asset, so the commit can include every referencer that has to be resaved.
- `ue_asset_audit` with `checks: ["redirectors", "references"]` finds redirectors to fix up and
  references to missing assets before a commit.

## Verify your work

- [ ] `git status` shows only files you meant to change; unrelated dirty `.uasset`s were reverted.
- [ ] No `Binaries/`, `Intermediate/`, `Saved/`, `DerivedDataCache/`, `.sln`, `.vs/` files staged.
- [ ] `git lfs ls-files` includes every new `.uasset`/`.umap`; `git check-attr` shows `lockable`.
- [ ] You hold (or released after pushing) the LFS lock for every binary asset you changed.
- [ ] Moves/renames: redirectors fixed and referencers committed in the same commit.
- [ ] The commit message lists changed assets and whether a map/`__ExternalActors__` changed.
