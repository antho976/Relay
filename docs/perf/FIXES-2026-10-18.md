# Fixes 2026-10-18: the disk and RAM agents leave behind

After some days of agents working without a restart the machine lagged: things took longer to
open, and the desktop stalled while agents built. Relay's own processes were not the cause (the
engine at 77 MB, the store at 139 MB). What the agents left behind was: their builds on disk,
their scratch space in RAM, and the size of every test link.

Machine: Ryzen 7 9800X3D (16 threads), 30.5 GiB RAM with 30.5 GiB zram swap (zstd, swappiness
150), `/` and `/home` on one 1.81 TiB btrfs (`compress=zstd:1`), `/tmp` a 15.6 GB tmpfs, rust 1.99,
dev profile (`opt-level` 1, dependencies at 3). Peers were building throughout; the load average
during the paired runs below was 44–67.

### Why it grew

- **A kept checkout kept its build.** `session.close` purges build output only when it removes the
  checkout. The shell's "Discard session" keeps it (`remove_worktree:false`), as does a close
  refused for uncommitted work, and nothing came back for the `target/` or the scratch directory.
- **Each test executable was 427 MB, 383 MB of it debug info** (`.debug_info` 130, `.debug_loc`
  117, `.debug_str` 81, `.debug_ranges` 29, `.debug_line` 24; `size -A` of `deps/store-*`).
  `relay-core` alone has 50 integration-test files, each its own executable linking the engine.
- **Cargo never deletes an artifact, and package selections fork them.** `cargo test -p relay-bus
  -p relay-core` resolves dependency features apart from a plain `cargo test` (`uuid`, `tempfile`,
  `gix`, `tokio`, `regex`, `tracing`… differ in the fingerprints), so every dependent unit gets a
  new hash and a whole new set of test executables is linked beside the old one. One live
  checkout wrote 202 executables, 75.8 GB, in 55 minutes over three `cargo test` runs; a closed
  one held 409, 173 GB, from about a day's work.
- **The links ran 14 at a time at 0.8–1.6 GB each** (`ld.lld` in the screenshot at 16:11), on top
  of everything above.

## Cleaned by hand (16:26–16:33)

| | before | after |
|---|---:|---:|
| `/tmp` (tmpfs) | 13.5 GB | 2.0 GB |
| RAM in use | 16.2 GB | 10.9 GB |
| swap in use | 21.8 GB | 7.9 GB |
| zram's own RAM | 7.4 GiB | 3.0 GiB |
| disk in use | 1 672 GB (91 %) | 1 128 GB (62 %) |

Removed: the scratch directories of every checkout no Claude process runs in, the `target/`
(and `.mt-target/`) of the ten closed checkouts, and the `target/` of the seven subagent
checkouts. Checkouts, uncommitted changes and branches stayed. Not removed: the leaked
`/tmp/.tmp*` directories (the session's command classifier refused a bulk delete in `/tmp`).

## Changes

1. **`disk_sweep`** (`crates/relay-core/src/disk_sweep.rs`), on the retention timer (5 minutes after
   start, then hourly), a minute after any session closes (`retire_session`), and on
   `app.reconcile`:
   - a checkout whose sessions are all closed loses its git-ignored build dirs
     (`worktree::ignored_build_dirs`), as does one in `.claude/worktrees/` or Relay's own areas no
     session owns once nothing was built there for a day; a checkout outside those areas is the
     user's and is left alone;
   - a live checkout, and the primary, keep their builds but only the 3 newest test executables
     of each name;
   - a closed Claude session's `<tmp>/claude-<uid>/<slug>/<uuid>/` is removed, read-only fixtures
     included.

   Nothing is purged while any process's cwd is inside the checkout, nor trimmed while cargo or
   rustc runs there or one of its test executables is running.
2. **`[profile.dev] debug = "line-tables-only"`**: backtraces keep files and lines; a debugger
   loses variables (`CARGO_PROFILE_DEV_DEBUG=true` brings them back).
3. **`.cargo/config.toml`: `[build] jobs = 8`** instead of one per core (below).
4. **`unreal_process.rs`'s test puts `HOME` back** before its temp dir is deleted.
5. **`scripts/perf/test-exe-size.py`**: a ratchet on the largest test executable (184 MB, budget
   210) and on all 62 together (9.5 GB, budget 11), meant to run in CI after the tests.

## Before and after: edit `relay-core`, rebuild its tests

`touch crates/relay-core/src/lib.rs; cargo test --no-run -p relay-core`, 8 jobs, `nice 10`, the
two profiles in separate target dirs, alternated, three rounds each
(`runs/2026-10-18-disk/journey.txt`). Peak RSS is the sum over every `rustc` and linker process
working in the checkout, sampled every 0.5 s.

| | full debug info | line tables only | change |
|---|---:|---:|---:|
| wall time | 21.0 s (20.4–25.0) | 7.5 s (7.5–7.7) | −64 % |
| peak RSS, compilers and linkers together | 12.5 GB (12.2–13.2) | 5.8 GB (5.5–6.0) | −53 % |
| largest single process | 1.69 GB | 0.93 GB | −45 % |
| written per rebuild (50 executables) | 22.4 GB | 8.4 GB | −62 % |
| one executable | 448 MB | 168 MB | −62 % |

The proxy, bytes linked, moved with the wall time and the RAM, and is deterministic for a given
toolchain; it is what the CI ratchet counts.

The same journey with line tables only at cargo's default of one job per thread (16), three more
rounds right after (load average 28–43):

| | 8 jobs | 16 jobs |
|---|---:|---:|
| wall time | 7.5 s (7.5–7.7) | 9.0 s (8.6–10.3) |
| peak RSS, compilers and linkers together | 5.8 GB (5.5–6.0) | 12.7 GB (12.3–13.4) |

Sixteen links at once do not finish sooner than eight on this machine and hold twice the memory,
so the repository builds with eight. A cold build of every dependency was not measured at both
settings; at eight jobs it took 112 s (`relay-core`'s tests, line tables only, load ~40).

## Left

- **One executable per integration-test file.** Linking 50 copies of the engine is still most of
  a `relay-core` rebuild; one `tests/it/main.rs` with the files as modules would be one link. It
  touches every test file (over a session's caps) while peers are editing them, and the tests that
  set process-wide state (`HOME` in `usage_source.rs`) would need it scoped first.
- **Feature-unifying the workspace** (a `cargo-hakari` workspace-hack crate) would stop package
  selections forking the build at all; the trim bounds what the forks cost instead.
- **Builds across sessions** are capped only one at a time (eight jobs each); two sessions
  linking at once still add up, to about what one did before.
- **Test runs that are killed** (a tool timeout, `| head`) leave their temp dirs in `/tmp`;
  systemd-tmpfiles removes them after 10 days.
- `.relay/build-seed` (78 GiB apparent, its generations share extents) and the primary's
  `target/` were not touched by hand; the sweep trims the primary's test executables.
